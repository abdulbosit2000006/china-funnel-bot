# China Funnel Bot — архитектура v2 (Cloudflare, $0)

Дата: 2026-10-03. Решение Абдула: хостинг **Cloudflare**. Этот файл заменяет разделы G, H, K, M, R, U в [audit-v1.md](audit-v1.md). Остальное в силе: воронка (O), аналитика (P), правила research (I), движок расчётов (J), безопасность (Q). Код не писался.

Метки: **VERIFIED** — проверено сегодня по официальной документации Cloudflare (ссылки в конце), **ESTIMATED** — моя оценка.

## 1. Главная идея

Сервер делает только лёгкую работу — **воронку**. Тяжёлую работу (research, расчёты, сборку PDF и черновики постов) делает Claude в этом проекте, а вы её проверяете. Такой процесс вы уже используете для постов.

```
          ┌──────────── в Claude (этот проект) ────────────┐
          │ research → расчёт → PDF → черновик поста        │
          │ (источники, метки VERIFIED/ESTIMATED/UNKNOWN)   │
          └───────────────┬─────────────────────────────────┘
                          │ вы проверяете и отправляете PDF боту: /upload <slug>
                          ▼
Telegram ──webhook──▶ Cloudflare Worker (TypeScript)
                        • проверка secret token, дедуп update_id
                        • /start <campaign> → PDF по file_id + кнопка «Хочу обсудить»
                        • кнопки follow-up, квалификация, уведомление вам
                        • админ-меню: лид-магниты, кампании, лиды, статистика, публикация поста
                        ▼
                     Cloudflare D1 (SQLite)  ◀── Cron Trigger раз в минуту: follow-ups
                     Cloudflare R2           ← архив PDF и картинок
```

## 2. Компоненты

| Компонент | Что делает | Бесплатный лимит (VERIFIED) | Хватит ли |
|---|---|---|---|
| **Workers Free** | webhook бота, админ-команды, cron | 100 000 запросов/день, 10 мс CPU на запрос, 5 cron-триггеров, 50 подзапросов на вызов | Да: один апдейт — это несколько запросов к БД и Telegram, CPU уходит мало (ESTIMATED) |
| **D1** (вместо Neon) | вся база | 5 ГБ, 5 млн чтений строк/день, 100 000 записей/день | Да, с большим запасом. Одна база у одного провайдера, без холодного старта |
| **R2** | оригиналы PDF, картинки | 10 ГБ, 1 млн записей и 10 млн чтений в месяц, исходящий трафик бесплатный | Да. Клиентам PDF всё равно уходит по Telegram `file_id` |
| **Cron Trigger** `* * * * *` | раз в минуту: отправка follow-up, свежесть материалов | входит в 5 триггеров | Да |
| **Queues** | не нужны в MVP | на Free есть: 10 000 операций/день, хранение 24 ч | Резерв |
| GitHub → Cloudflare | деплой при push в `main` (Workers Builds или GitHub Action) | бесплатно | — |

**Если упрёмся в 10 мс CPU** (маловероятно для воронки): Workers Paid стоит $5 в месяц, там 5 минут CPU (VERIFIED). Код менять не нужно.

## 3. Язык и стек

- **TypeScript** + библиотека **grammY** (Telegram, работает в Workers через webhook). Python Workers пока в beta, поэтому не берём.
- Схема БД та же, что в разделе H аудита. Перенос на SQLite/D1: `jsonb` → `TEXT` с JSON, деньги хранятся в центах/тийинах как целые числа. Блокировки `FOR UPDATE SKIP LOCKED` в D1 нет. Захват задачи делается атомарным `UPDATE … SET status='SENDING' WHERE id=? AND status='PENDING' RETURNING *`.
- Миграции: `wrangler d1 migrations`.
- Секреты: `wrangler secret` / Cloudflare Dashboard. В GitHub не попадают: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ADMIN_TG_IDS`, `CHANNEL_ID`.
- Ключ AI на сервере в MVP **не нужен**: research идёт в Claude. Это экономит деньги и снижает риск утечки.

## 4. Как появляется лид-магнит (без серверного AI)

1. Вы пишете здесь, например: «Сделай research по Canton Fair, весна 2027».
2. Claude ищет официальные источники, считает бюджет поездки или бизнес-модель (код расчётов из раздела J, запускается здесь), собирает PDF и черновик поста. Каждая цифра имеет метку и источник.
3. Вы проверяете PDF и пост.
4. Вы отправляете PDF боту командой `/upload canton-fair-2027`. Бот сохраняет `file_id`, версию и копию в R2.
5. `/campaign canton-fair-2027` → бот создаёт код кампании и deep link `t.me/<bot>?start=cf27_p1`.
6. `/post` → бот показывает превью поста с кнопкой. Вы нажимаете APPROVE, и пост выходит в канал.

Автоматический research на сервере добавим позже (Workers Paid или отдельный сервис), если воронка покажет результат.

## 5. Follow-up (2–3 часа)

Без изменений по логике (раздел M аудита). Отличия в реализации:
- При выдаче PDF создаётся строка `followups` с `due_at = now + 150 мин`.
- Cron раз в минуту забирает до 50 записей, у которых наступил `due_at`. Перед отправкой проверяет: человек не сконвертировался, не нажал NOT NOW, не заблокировал бота, ему не писали follow-up последние 24 часа, сейчас не тихие часы. После этого отправляет.
- Максимум один follow-up на один PDF.

## Обновление 2026-10-03: бот сам находит выставки (решение Абдула)

Абдул: бот **сам** находит выставку, полезную и востребованную у предпринимателей из Узбекистана, делает к ней пост и PDF с чётким расчётом поездки (§13–16 ТЗ). Все файлы хранятся в нашем облаке. Раздел 4 выше («research в Claude») остаётся запасным ручным режимом. Основной режим — серверный, фазы 6–8.

### Как это ляжет на Cloudflare

```
Админ: «🔎 Найди выставки»  (или раз в неделю по cron)
   → Cloudflare Workflow "exhibition-research" (шаги переживают сбои, ожидание сети не ограничено по времени)
      1. DISCOVER: Claude + web_search → 5–10 кандидатов только с официальных сайтов организаторов
      2. SCORE (код): совпадение категорий выставки с интересами аудитории + сигналы спроса (ниже)
      3. Админу карточки кандидатов → вы выбираете одну
      4. RESEARCH: даты, фазы, площадка, категории, регистрация (каждый факт = URL из citations)
      5. TRIP INPUTS: перелёт, отель на 2, транспорт, виза, eSIM — с датой и источником
      6. CALCULATE (код, не LLM): бюджет на 2 человек, формулы видны в превью
      7. PDF: HTML-шаблон → PDF → R2 (оригинал) → Telegram file_id
      8. POST: черновик → превью → APPROVE / EDIT / REJECT → канал
```

### «Реально хорошая и востребованная» — чем меряем (без выдумок)

| Сигнал | Источник | Метка |
|---|---|---|
| Масштаб: экспоненты, посетители, площадь | официальная статистика организатора | VERIFIED / MARKET DATA |
| Категории совпадают с нашей аудиторией (станки, линии, сырьё, упаковка…) | официальный список разделов | VERIFIED |
| Импорт Узбекистана по этим товарным группам | UN Comtrade / stat.uz | MARKET DATA (с годом) |
| Участие/посетители из Центральной Азии, если организатор публикует | организатор | VERIFIED или UNKNOWN |
| Наши данные: какие темы скачивают и где больше лидов | своя аналитика (Phase 5) | CALCULATED |

Итоговый балл — сумма правил в коде, с объяснением по каждому пункту. Это ориентир для вашего выбора, а не гарантия спроса.

### Стоимость и ограничения (честно)

- **AI API становится обязательным:** нужен ключ Anthropic (в старом боте он был). Оценка: $1–3 за один пакет «выставка + PDF + пост», при 4–8 пакетах в месяц ≈ $5–25 (ESTIMATED). На ключе стоит месячный лимит.
- **Workers Free даёт 10 мс CPU на шаг Workflow (VERIFIED).** Разбор больших ответов AI и сборка PDF, скорее всего, не уложатся. Значит, для фаз 6–8 почти наверняка понадобится **Workers Paid за $5 в месяц** (5 минут CPU на шаг, VERIFIED). Фазы 1–5 работают на Free.
- **PDF:** вариант 1 — Cloudflare Browser Rendering (HTML → PDF; Free 10 браузер-минут в день, VERIFIED; генерация PDF через него — проверю на фазе 8). Вариант 2 — библиотека pdf-lib прямо в Worker.
- **Цены перелётов и отелей** — самая ненадёжная часть. Поиск по страницам агрегаторов даёт случайные цифры. На фазе 6 выберем источник: например, API цен авиабилетов (Aviasales/Travelpayouts) и фиксированный сценарий отеля по официальным тарифам. В PDF всегда пишется «Example for 2 people, indicative prices as of [DATE]».
- **Хранилище:** все PDF, картинки и research-пакеты лежат в нашем аккаунте Cloudflare (R2 + D1). Бесплатно до 10 ГБ файлов и 5 ГБ базы (VERIFIED).
